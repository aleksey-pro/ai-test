# Этап 15. Расширенный прогон и политика дефектов

Успешный узкий прогон расширяется до релевантного набора тестов. Его падения также возвращаются в цикл анализа.

Если причина — дефект приложения, исходный код приложения flow не меняет без явного запроса: локализует проблему и даёт рекомендацию. Внешний blocker при корректном тесте оформляется как `test.fixme()` с комментарием.

Риски pre-check сохраняются независимо от итогового статуса запуска.
