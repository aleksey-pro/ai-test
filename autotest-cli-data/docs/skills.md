# Используемые скиллы autotest-cli

Ниже приведены скиллы основного flow. Каждый из них обновляет единый отчёт текущего запуска, а не создаёт отдельный отчёт.

| Скилл | Роль | Результат |
| --- | --- | --- |
| `testit-extractor` | Находит проект и секцию TestIt, рекурсивно извлекает Front-end-кейсы, применяет фильтры. | Markdown-кейсы в `test-cases/testit/`. |
| `test-classificator` | Определяет подходящий тип автоматизации для каждого кейса. | Кейсы разложены по каталогам `test-type`; выбран непустой набор. |
| `playwright-test-precheck` | Проверяет кейсы против кода, маршрутов, UI и существующих тестов; выявляет риски и повторы. | Статусы `valid`, `valid-with-note`, `invalid`, допущения и риски. |
| `swagger-parser` | Валидирует или обновляет Swagger/OpenAPI-контракт при необходимости API-моков. | Подтверждённый контракт либо зафиксированный blocker. |
| `playwright-mock-generator` | Создаёт детерминированные Playwright-моки на основе контракта. | Fixtures, валидация, узкие routes и provenance в `mocks/`. |
| `playwright-test-generator` | Генерирует и обновляет Playwright `spec.ts` с учётом pre-check и доказательств. | Покрывающие кейсы тесты, статусы `created`/`modified` и узкий scope. |
| `playwright-test-healer` | Запускает тесты, анализирует падения и минимально исправляет тестовый код. | Успешный прогон, `test.fixme` или blocker с историей попыток. |

## Вспомогательный инструмент

`@playwright/cli` не является обязательным скиллом. Если он уже установлен, flow использует его для runtime-данных UI (accessibility snapshot, URL, состояние). Если недоступен, применяются стандартные Playwright trace и screenshots; работа flow не прекращается.
