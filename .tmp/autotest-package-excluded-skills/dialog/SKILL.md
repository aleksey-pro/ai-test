# Dialog

Скилл для создания диалогового интерфейса сбора данных от пользователя. Скилл задает вопросы по очереди и ожидает ответа перед переходом к следующему шагу.

Скилл управляет только диалогом: порядком вопросов, валидацией, сохранением ответов и подтверждением. Конкретная бизнес-логика — например, анализ проекта, создание задачи или генерация отчета — определяется запросом пользователя или вызывающим сценарием.

## Основные принципы

1. **Всегда задавай один вопрос за раз** - Не переходи к следующему вопросу, пока не получишь ответ на текущий
2. **Ожидай ответа** - Просто задавай вопрос и жди ответ пользователя в чате
3. **Валидируй данные** - Проверяй корректность введенных данных перед переходом к следующему шагу
4. **Запоминай контекст** - Сохраняй все полученные данные для использования в дальнейшем
5. **Не спрашивай то, что можно безопасно определить** - Получай доступные данные из контекста, файлов проекта или разрешенных инструментов самостоятельно
6. **Доводи сценарий до результата** - После подтверждения выполни согласованное действие, если оно входит в запрос и доступно; не останавливайся на сводке параметров

## Структура диалога

### Шаг 1: Определение цели диалога

В начале диалога определи, какую информацию тебе нужно собрать. Составь список вопросов, которые нужно задать пользователю.

Если цель уже понятна из запроса или предыдущих сообщений, не переспрашивай ее. Сначала извлеки известные параметры из контекста и спрашивай только о действительно недостающих решениях.

**Пример целей:**
- Сбор данных для создания задачи
- Сбор информации о пользователе
- Сбор данных для генерации отчета
- Сбор параметров для выполнения операции

### Шаг 2: Определение последовательности вопросов

Определи порядок вопросов. Начни с общих вопросов и переходи к более конкретным.

**Рекомендуемый порядок:**
1. Основные/обязательные данные
2. Дополнительные данные
3. Уточняющие данные
4. Подтверждение

### Шаг 3: Задать вопрос и ожидать ответа

Для каждого вопроса:
1. Сформулируй вопрос четко и понятно
2. Предложи варианты ответа (если применимо)
3. Дождись ответа пользователя
4. Валидируй полученные данные
5. Переходи к следующему вопросу

## Формат вопросов

### Простой вопрос
Задай вопрос в чате и жди ответа. Пример:

```
Какое название у задачи?
```

### Вопрос с выбором из вариантов
Предложи варианты в чате:

```
Какой приоритет у задачи?
- Низкий
- Средний
- Высокий
- Критический
```

### Вопрос с подсказкой
Добавь подсказку о формате:

```
Когда нужно выполнить задачу?
Укажите дату в формате ДД.ММ.ГГГГ, например: 15.06.2025
```

## Управление диалогом

### Начало диалога

В начале сообщи пользователю о начале сбора данных:

```
Начинаю сбор информации. Отвечайте на вопросы по очереди.
Для отмены введите "отмена" или "отменить".
```

### Переход к следующему вопросу

После получения ответа:
1. Кратко подтверди получение данных
2. Сообщи о переходе к следующему вопросу
3. Задай следующий вопрос

### Завершение диалога

После сбора всех данных:
1. Кратко суммируй полученные данные
2. Спроси подтверждение корректности
3. После подтверждения выполни целевое действие, если оно входит в запрос пользователя и не требует дополнительного разрешения
4. Если скилл вызван другим сценарием, передай ему собранные данные в понятной структурированной форме
5. Сообщи фактический результат выполнения, а не только перечень собранных параметров

## Граница ответственности

Не встраивай в скилл предметные правила отдельных операций. Диалог должен оставаться универсальным и принимать из запроса или вызывающего сценария:

- цель сбора данных;
- обязательные и необязательные параметры;
- допустимые значения и правила валидации;
- значения по умолчанию;
- действие, выполняемое после подтверждения.

Если целевое действие нельзя выполнить из-за отсутствия инструмента, прав доступа или обязательного параметра, ясно сообщи об ограничении и запроси только недостающее. Не имитируй успешное выполнение.

## Пример диалога

### Пример: Сбор данных для создания задачи

**Начало диалога:**
```
Начинаю сбор информации для создания задачи. Отвечайте на вопросы по очереди.
Для отмены введите "отмена".
```

**Вопрос 1:**
```
Какое название у задачи?
```

**Ожидание ответа...**

**Вопрос 2:**
```
Опишите задачу подробнее. Что нужно сделать?
```

**Ожидание ответа...**

**Вопрос 3:**
```
Какой приоритет у задачи?
- Низкий
- Средний
- Высокий
- Критический
```

**Ожидание ответа...**

**Вопрос 4:**
```
Кому назначить задачу?
```

**Ожидание ответа...**

**Завершение:**
```
Собранные данные:
- Название: [название]
- Описание: [описание]
- Приоритет: [приоритет]
- Исполнитель: [исполнитель]

Верно? (да/нет)
```

## Обработка ошибок

### Пользователь ввел некорректные данные

1. Сообщи об ошибке
2. Объясни, какой формат ожидается
3. Повтори вопрос

### Пользователь хочет отменить

1. Подтверди отмену
2. Спроси, нужно ли сохранить введенные данные
3. Заверши диалог

### Пользователь пропускает вопрос

1. Спроси, хочет ли он пропустить вопрос
2. Если пропуск разрешен - используй значение по умолчанию или оставь пустым
3. Переходи к следующему вопросу

## Техническая реализация

### Взаимодействие с пользователем

Просто задавай вопросы в чате и жди ответов. Это естественный диалог.

### Сохранение данных

Храни все полученные данные:

```
const collectedData = {
  // Поле: значение
};
```

### Валидация данных

Проверяй данные после каждого ответа:
- Обязательные поля заполнены
- Формат данных корректен
- Данные в допустимых пределах

## Рекомендации

1. **Будь терпелив** - Всегда дожидайся ответа пользователя
2. **Будь конкретен** - Формулируй вопросы четко и понятно
3. **Предлагай варианты** - Это упрощает выбор для пользователя
4. **Подтверждай** - Кратко подтверждай получение данных
5. **Суммируй** - В конце покажи сводку собранных данных
6. **Дай возможность исправить** - Разреши пользователю вернуться к предыдущим вопросам
